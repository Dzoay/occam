# Proposal B: records first

A design proposal for `proving-ground.design`, written to be attacked. Findings are cited by id (S1 to S6, P1 to P12, in
`docs/evidence/2026-11-09-*.md`) and lessons by L-number.

## 1. What this design optimises and what it gives up

It optimises for the shortest path to the bracket test, the least code, and a kernel an agent can read: every entity is one
plain record, every failure describes what it names, and the native file is its own dump. It takes the smallest thing each
finding showed was needed: S1's list of what topology holds, S2's tolerance model, P2's pure phases, P11's ordered map.
Later needs stay open behind interfaces that hide layout: records are read by value, so struct-of-arrays can replace them
inside one module; geometry is reached through S4's two layers, so batches across instances can be built later from what a
surface presents; phases are pure functions of content, so caching can come later.
It gives up struct-of-arrays read scaling on memory-bound traversals (S3-P3: 1.62 against 1.88 times at six cores with
buffers and a merge), S4's geometry column store, mesh-backed surfaces in the first release, and a binary native format.

Changes from PLAN §4:

- **`occam-check` becomes a module of `occam-topo`.** Parity row 1.10 asks for closure, Euler, orientation and
  self-consistency, not self-intersection, so the checker needs records and geometry and nothing above them.
- **The execution layer lives in `occam-math`.** Its contract is DETERMINISM.md rule 4 and `gates determinism` already
  builds this crate at one and many threads, so both approved dependencies that can touch bits sit in the one crate the
  contract gates. `rayon` is native-only, as `gungraun` is (P11: its explicit pool refuses on wasm). `occam-math` gains a
  dependency on `occam-report`, which §4 allows.
- **Tolerance:** the band and position uncertainty are methods of `Tolerance` (S2); the certified radius is an `Interval`
  while computing and one `f64` on a stored vertex. Geometry codes join the one catalogue that `gates errors` reads.
- **Mesh-backed surfaces leave the first release.** No parity row needs them and S4 showed the seam carries them. Adding the
  family later needs one defaulted question on the seam, which edits no other family.
- **The native format is the records as JSON,** through `serde_json` with `float_roundtrip`, already on, so every finite
  number round-trips exactly and it is the readable dump of parity row 2.17 and L8: one format, not two.

## 3. The seams

Each block names its crate. A function whose body is `todo!()` is a signature only. Changes to existing crates are stated.

### (a) Units and quantities

Existing types stay, and so does conversion at the API: a request carries its units, and `Length::new` and `Angle::new`
remain the one place numbers become quantities. S1 found the typed layer stopped where formulas began, for want of dot,
cross and norm; rather than a dimensional algebra, `Vec3` serves the inside of a formula, typed again at its ends. Of S4's
asks, the unit axis and per-parameter derivative are new types. Typed parameters are rejected: the case behind them, a
cone's `v` compared with an angle tolerance, is fixed by each parameter saying what it measures (`ParamMeasure`, §3c).

### (b) Maths

`Real` gains comparison and selection, which S4 and P5 had to build through `to_array`, and the two owned functions of S5.
`Lanes::from_fn` becomes a plain loop: `array::from_fn` falling out of line cost a rational kernel 2.3 times (P4).

Decisions follow S2: exact on stored numbers (interval filter, then expansions); a computed value's interval straddling
the band is `Undecided`. Predicates are written once over `Ring`, and a batch filters in
four lanes with the exact path inline (P6). No exact towers (S2: work grows about five times a step).

The execution layer is P11's interface over `rayon`. It is a concrete type, not a trait, so no kernel function is generic
over its runner, and a swap to a small pool is still one module.

```rust
// occam-math: new. Only this module names `rayon`.
/// Changes speed, never bits (P11).
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Grain {
    Auto,
    /// One item a task, for items of 10 us and more: a face, a pair, a region (P2, P9, P11).
    Each,
    /// 256 to 1024 for predicate batches (P6).
    Fixed(usize),
}

/// An ordered map: results in index order, arrival order invisible, no reductions, `'static` closures.
#[derive(Clone, Debug)]
pub struct Exec { runner: Runner }

#[derive(Clone, Debug)]
enum Runner {
    /// The one-thread baseline, and the runner inside each browser worker (P10).
    Serial,
    #[cfg(not(target_family = "wasm"))]
    Pool(std::sync::Arc<rayon::ThreadPool>),
}

impl Exec {
    pub const fn serial() -> Self {
        Self { runner: Runner::Serial }
    }

    /// # Errors
    /// `Code::ThreadsUnavailable` if the pool cannot start. On wasm this is `Serial`.
    pub fn threads(n: usize) -> Result<Self, Report> { todo!() }

    pub fn map<R, F>(&self, n: usize, grain: Grain, f: F) -> Vec<R>
    where
        R: Send + 'static,
        F: Fn(usize) -> R + Send + Sync + 'static,
    {
        match &self.runner {
            Runner::Serial => {
                let _ = grain;
                (0..n).map(f).collect()
            }
            #[cfg(not(target_family = "wasm"))]
            Runner::Pool(pool) => {
                use rayon::prelude::*;
                let (lo, hi) = match grain {
                    Grain::Auto => (1, usize::MAX),
                    Grain::Each => (1, 1),
                    Grain::Fixed(k) => (k.max(1), k.max(1)),
                };
                // `collect` of an indexed iterator: the one rayon form P11 found order-safe.
                pool.install(|| (0..n).into_par_iter().with_min_len(lo).with_max_len(hi).map(f).collect())
            }
        }
    }
}

/// A lane kernel at the widest instruction set the CPU has, with the baseline's bits (P4). The compiled crate wraps the
/// call in `fearless_simd::dispatch!`; the kernel and its callees are `#[inline(always)]`.
#[inline(always)]
pub fn widest<T>(kernel: impl FnOnce() -> T) -> T {
    kernel()
}
```

### (c) Geometry

S4's two layers, with three changes:

- **Everything stored is `World`.** The traits lose their frame parameter, removing S4's `E0119` case. Local-frame
  instancing is a later decision (P8), as a `Placed` family.
- **Explicit order, and any order.** P8's first-ranked saving (33 to 34% of whole-run time) is an evaluator that computes
  only the order asked for, plus a parameter-only query. The three fixed rungs stay for hot paths, and a scalar
  `eval_order` meets approved parity rows 2.1 and 2.2 (O21).
- **Fewer questions.** `analytic()` serves the closed forms, `bspline()` the hybrid and parity 2.1's conversion. S4's
  `triangles()` and `specialised()` have no first-release user; a defaulted question added later edits no family.

Batches are per surface: a slice in `Lanes<2>`, 1.2 to 3.3 times faster than one point at a time (P9). There is no column
store. S4 item 4 said homogeneous data cannot be recovered from `dyn Surface`; it can, without a downcast, by copying what
`analytic()` and `bspline()` present. Against a store now: S4's was 2.6 times slower than per-call on analytic surfaces,
S3-P3 found no gain on baseline x86-64, and P5 found batching under 3% of intersection. Sorting by `batch_key` (14 to 18%,
S4) stays.

### (d) Topology

S3-P3's copy-on-write chunks of array-of-structs records (O22, fixed), 1,024 a chunk: S3-P3 found that best for edits
that scatter, as a boolean's do (14 against 41 microseconds an edit at 100 edits). Records are read by value, so nothing
outside the table module learns the layout.

The records hold S1's list: shared vertices (item 1); the sheet a face lies on (item 2, the most damaging removal); loops,
outer first (item 3); two uses per edge (item 4); real seam edges, no face crossing its own seam (item 5); a vertex may
join four edges, even of two shells (item 6, a checker rule, not a field); a parameter curve per edge use (item 7, 3.45
times faster). Poles and apexes are declared degeneracies (S4), never zero-length edges. Tolerance data: one model
`Tolerance`, a measured deviation per edge (item 9: up to 140 times the tolerance with right volumes), a fit error on
sampled curves (item 10), and a certified radius per stored vertex (S2's 32-byte vertex). Nothing grows.

### (f) Operations

A request is a list of steps with optional labels, read through `serde`, validated before any geometry with a code per kind
of invalid input (S6). Steps stop at the first failure; the result holds the model after the last success and an outcome
per step run, so the input never changes and an agent can resume.

```rust
// occam-ops.

    /// Omitted: 1e-6 mm and 1e-9 rad (O12).

    pub steps: Vec<Step>,
}

    Cut { target: Operand, tool: Operand },
    /// Every edge gets an outcome; the model changes only if all succeed (L6).

    // and the primitives, extrude, revolve, fuse, common, chamfer
}

/// An earlier step's label, or a solid by id.

```

The boolean is P2's shape (a): ordered maps from frozen input to frozen output, phase 3 as three rounds with a frozen
vertex table between them, ids only in the final `Edit`, every failing item reported in candidate order. Only faces in a
candidate pair are trimmed and split; the rest keep their ids and are labelled by propagation, so work follows the edit, not
the model (P1's plate ladder: 38 times the work for the same hole).

```rust
// occam-ops::boolean.
pub fn boolean(kind: BooleanKind, target: SolidId, tool: SolidId, model: &Arc<Snapshot>, exec: &Exec)
    -> Result<Outcome<(Snapshot, History)>, Report>
{
    let ctx = Context::new(model, &[(target, Role::Target), (tool, Role::Tool)]);
    let pairs = broad(&ctx, exec)?;                          // conservative bounds
    let trims = prepare(&ctx, &pairs, exec)?;                // touched faces only, from parameter curves
    let sections = intersect(&ctx, &pairs, exec)?;           // distinct surface pairs, then boxed edge tests
    let split = split_edges(&ctx, &trims, &sections, exec)?; // three rounds, frozen vertex table between
    let regions = split_faces(&ctx, &split, exec)?;          // one face a task: content in, local indices out
    let labels = classify(&ctx, &regions, exec)?;            // one region a task, then propagation
    let mut edit = model.edit();
    stitch(kind, &ctx, &regions, &labels, &mut edit)?;       // sequential: the only place ids are given
    let (next, history) = edit.commit();
    check(&next, exec)?;                                     // every success, release builds too
    Ok(Outcome::new((next, history)).with_diagnostic(ctx.tally_report()))
}
```

The hook for later work avoidance (P8) is a rule: an item function takes content and returns indices local to its item,
never a model id, and identity is an id or `Content`, never a pointer, so item-level caching later changes no phase. No cache
now: P8 found it saves about nothing once explicit order and edge box tests are in, except on NURBS marching. A radius too
large is `blend.radius-too-large` with the edge, the largest feasible radius and `reduce-radius { edge, radius }` (L3).

### (g) The report

`occam-report` gains S6's fields and loses one S6 found unused. It names no geometry type: a description is a closed `Form`
(vocabulary, like `RemedyKind`) plus named values. `SCHEMA` becomes 2.

```rust

impl Report {
    pub fn error(code: Code, fault: Fault) -> Self { todo!() }
```

**Filled in where the failure is found.** Geometry describes itself (`shape()`); `Context::describe(entity)` in
`occam-topo` adds the extent and the origin (the solid's `step`, the operation's roles). An entity that exists only inside
the failing operation, such as a section curve, is described from the phase output holding it, as `Role::Found` with
generation 0 and its index in that frozen output as slot: deterministic, never mistaken for a model entity. A site costs one
line per entity:

```rust
Report::error(Code::DanglingSection, Fault::NumericallySensitive)
    .with_entity(a.entity())
    .with_entity(b.entity())
    .describing(ctx.describe(a.entity()))
    .describing(ctx.describe(b.entity()))
    .describing(ctx.found(index, &section_curve))
    .with_partial(Partial { stage: Stage::EdgeSplit, failing: vec![a.entity(), b.entity()], values: gap })
```

**What it costs.** Code: a `shape()` per family (10 to 20 lines, 16 families, about 250 lines), `describe` and `found`
(about 80), and a line per named entity at each site. Size: a described cylinder face is about 330 bytes of JSON with round
numbers, 550 with 17-digit ones; a B-spline gives degrees, counts and extent, not its net, so under 400. A report naming two
faces and a found curve is about 1.5 KB, against about 300 for S1's. The success path is unchanged: `Report` is a `Box`.

**The rest of S6.** The step runner adds the tolerance in force to every report. Reasons are codes, not text. Invalid input
has its own codes, in `Stage::Validate`. An empty result is a `boolean.empty-result` note with the operands' separation.
Every operation adds a `measure.decisions` note with its `Tally` (P6). `gates errors` holds remedies to L2, as now.

**"Cannot decide at this resolution" (O11)** is `Sign::Undecided` in the maths, `Unresolved` in a section, and at the
operation an error with `Fault::NumericallySensitive`, partial values for the interval, the band and the position
uncertainty, and the remedies `move-apart { entity, direction, distance }` and `change-tolerance { tolerance }`, each with a
followed-remedy test.

**How an agent learns what an entity is:** reports describe what they name, step outcomes what they created, `occam
describe` anything in a saved model, and the native file is the records. All four call one `describe`.

### (h) Mesh, the renderer contract and the wasm facade

`occam-mesh` is P9's method: sample each shared edge once, mesh faces independently against those samples, merge by index.
It has P9's limits, checks every output in production, and measures chordal error to the triangle. Point location uses §3b's
predicates on real coordinates, not P9's integer grid, which caused all three of P9's failures.

```rust
// occam-mesh.
/// What stops one face's bad estimate becoming the model's allocation failure (P9's 12 GB).
pub struct Limits { pub samples_per_edge: u32, pub triangles_per_face: u32, pub smallest_edge: Length }

pub struct Range { pub entity: EntityRef, pub first: u32, pub count: u32 }

/// The renderer contract (P9, P12): flat, welded, closed, and checked rather than assumed.
pub struct Mesh {
    pub positions: Vec<f64>,   // welded, three per vertex
    pub normals: Vec<f32>,     // three per corner, from the surface, poles included
    pub indices: Vec<u32>,     // three per triangle
    pub faces: Vec<Range>,     // each face's triangles, in face order
    pub edge_points: Vec<u32>, // each edge's samples, as vertex indices
    pub edges: Vec<Range>,
}
```

The renderer may rely on what P9 lists, not on triangle shape or the angular limit at coarse deflection. Its own side is
P12's: buffers readable as storage and vertices, per-face ranges, bounded uploads, camera-relative coordinates (an `f64`
origin, `f32` offsets) and a frame loop that keeps submitting. GPU results are display-only.

`occam-wasm` binds only `occam`: stable Rust, simd128 by default, a pool of workers with separate memories, each running
`Exec::serial()` (P10). The page never runs wasm. Models and requests cross as text, meshes as transferred typed arrays.

```rust

impl Session {
```

Each worker samples every shared edge itself (1 to 3% of the work, P9, identical everywhere), so no edge data crosses
between workers. The page keeps the pool alive and splits a mesh into about 64 calls, which balanced uneven work and avoided
Firefox's long-call penalty of 1.4 to 2.3 times (P10). Other operations run on one worker.

## 4. Determinism

**Order.** `Exec::map` returns results by index. Merges run in candidate order (face slot order); the vertex merge sorts
and sweeps a frozen table. Methods are tried in list order on a pair ordered by family, batch key and `Content` word by word,
a total order. Tables iterate in slot order; free slots are reused last-in first-out. No hashed collections, as now.

**Ids.** Given only in `Edit`, on one thread, as a step writes its result. Phases use local indices; transient entities in
reports use generation 0 and their index in a frozen output.

**Hashed.** `Snapshot::digest`: every live record in slot order, every geometry record's `Content`, and the tolerance, NaNs
canonicalised. Also `History`, mesh buffers, and report and outcome JSON, which must be byte-identical at any thread count.
`gates determinism` gains the bracket test and a corpus sample at 1 and N threads, on x86-64 and wasm32 baseline and simd128,
and with `widest` forced to each instruction level (P4 measured them bit-identical). The owned `sin_cos` and `atan2` join
the stream, hashed against a separate implementation (S5).

**Kept out.** GPU output (P12), timings, thread count, instruction level, arrival order and pointers: P8 found a cached curve
taking a slower path because `Arc::ptr_eq` said different where content was equal, so `Arc::ptr_eq` and `std::ptr::eq` join
`disallowed-methods` in kernel crates.

## 5. Parallelism

Threads across items through `Exec`, lanes inside each task (L28): P4 measured the two multiplying to within about 1%.

| Work | Grain | Lanes | From |
|---|---|---|---|
| Boolean broad, prepare, pairs, edge tests | `Each` | bounds at 8 through `widest` | P2, P4 |
| Hybrid traces inside a pair | rounds of 32, nested map | none: marching is scalar | P5 |
| Edge split, three rounds | `Each`, sequential merges | none | P2 |
| Face split; checker | `Each`, one face a task | evaluation at 2 | P1, P2 |
| Classify | `Each`, one region a task | crossing number at 8 through `widest` | P2, P4 |
| Stitch and `Edit` | sequential | none | P2 |
| Predicate batches | `Fixed(256)` to `Fixed(1024)`, exact inline | filter at 4 | P6 |
| Tessellation, edges then faces | `Each`; browser pool of 64 calls | evaluation at 2 | P9, P10 |
| Anything else in the browser | one worker, `Serial` | simd128 build | P10 |

Lane width is a named constant per kernel class (P4): masks and reductions 8 through `widest` (5.8 to 5.9 times with AVX2
from a baseline build); predicate filters 4 (1.48 times, P6); surface slices 2 (P9); rational with derivatives 1 and analytic
with trigonometry precomputed 1, where two lanes lose 2 to 3 times (P4); marching scalar (P5). P4 and P9 differ on two lanes
for analytic surfaces only because P9 computed sine and cosine in lanes, so every lane kernel gets P4's vectorisation check
in `gates perf`. Finer grain inside one large face, the face split's ceiling (P1), waits for a real profile.

## 6. The open decisions

**O11.** Assumed yes, as §3g. If no, the kernel must pick a side: exact towers with a budget (S2: right where they finish,
one chain in four past 4e9 limb multiplications at 12 steps) or a forced snap, wrong against nominal in 8% of S2's chain
steps. `occam-math` gains towers, `occam-ops` a policy, and the `Undecided` errors become warnings on a success.

**O12.** Proposed: **1e-6 mm and 1e-9 rad**, as the request schema's default. In S1's sweep no answer was wrong from 1e-5 to
1e-9 mm, but results flagged open rose from 0 at 1e-6 to 3, 9 and 14 at 1e-7, 1e-8 and 1e-9: 1e-6 is the smallest
tolerance with none, and every success must pass the checker. S2's intervals failed inside the band at 1e-9 (11.1%) and not
at 1e-7 (0.2%), likely at its largest scale, 8192; on that reading 1e-6 mm leaves room to models of about 100 m. P9's mesher
failed on a 1e-7 mm gap and on 1e-8 mm edges, which a valid model at 1e-6 cannot hold apart. The cost: a band decision moves
a vertex sqrt(2 R eps), 3.5e-3 mm at R = 6 against 1.1e-3 at 1e-7 (S2). 1e-9 rad moves a point 1e-6 mm at 1,000 mm. If the
user picks 1e-7 mm, where every finding measured, only the default and fixtures change, and S1's three open results must
first be shown to be measuring noise.

**O14.** Assumed yes (S5): the only route to lane evaluation of analytic surfaces, smaller on wasm, and immune to std's
literal arguments being folded with the build machine's libm, which breaks the debug-and-release promise on wasm. If no:
`Real` loses both, analytic families loop over std a lane at a time (1.5 to 2.7 times slower), and `clippy.toml` and
DETERMINISM.md exempt them.

**O16.** Assumed: promised only for owned functions until the feature is real. Every function the kernel calls is IEEE or
owned and §4's gate compares operation digests across targets, so promising identity now is one sentence.

**O18.** Assumed nothing (P10). If COOP/COEP is required: a nightly threads build (O10), a shared-memory arm of `Runner`, and
one instance instead of the pool in `occam-wasm`; no kernel crate changes.

**O21.** Answered by the approved parity list: rows 2.1 and 2.2 ask for any derivative and offset surfaces in `geometry`,
the named feature O21 waits for. So families implement `eval_order` before the seam freezes. If the user answers "two
orders" and amends those rows: drop `eval_order`, and an offset's second derivative is a difference, about 1e-5 (S4).

**O22.** Fixed here: records. S3-P3's read-scaling gap is on a memory-bound read of about 20 ns a face; real per-face work is
far heavier (its surface-evaluation tasks reached 5.4 to 5.6 times, P2's analytic booleans 4.7 to 5.0), so store traversal
is not a phase's ceiling. Records take a snapshot in 183 against 1,191 microseconds at 1,024 a chunk and edit in place in
1.37 against 1.98 at 4,096, and one record is what a reader, a dump and an agent see. If struct-of-arrays is chosen, only
`Table` changes.

**O23.** Assumed as recommended: sorted calls, per-surface slices, no cross-instance store. If not narrowed: per-family
columns with lanes across instances (S4's store: 2.6 times slower on analytic surfaces).

**O24.** Assumed a reported result: `Unresolved` in the section, and `intersect.below-resolution` with the size `d` when it
changes topology. If a contact point is preferred, `Unresolved` merges into `Contact`, and P5's silent wrong shape (one,
under closed forms then the hybrid) stays silent.

**O25.** Proposed: no follow-up spike; coincident surfaces are a required case inside `booleans`, gated on S1's 32 cases.
The bracket test can meet one: a hole tool exactly as tall as the plate puts its caps on the plate's faces, like S6's
box-on-box case. Closed forms detect coincidence (`Section::coincident`); the split phase intersects boundaries within the
shared surface, and classify gains "on, same side" and "on, opposite side". No record changes: faces may share a surface.
Meanwhile the report offers `move-apart`; S6's enriched blind agent fixed this case in one attempt from a stated separation.

**O26.** Fixed here: descriptions (§3g). With ids and a query instead, `Description` becomes what `occam describe` returns,
and entities existing only inside a failed operation need a failure context kept for later queries. S6's blind agent
without descriptions declined c08 for a cause it invented.

## 7. Changes to the first-release milestones

1. **`maths`:** `Real`'s comparison, selection and owned functions (coefficients per O15), `Interval`, `Expansion`, `Ring`,
   `decide_all`, `Exec` over `rayon`, `widest`, `from_fn` as a loop. Exit adds owned-function hashes from a separate
   implementation and digests at every instruction level.
2. **`geometry`:** name its parity rows (2.1 to 2.4, 2.8); move mesh-backed surfaces after the release; add `occam-units`'
   new types. Exit: S4's conformance suite over every family, offset and revolution included; then freeze.
3. **`topology`:** records in chunks of 1,024, typed ids, `Edit`, `History`, the checker as a module.
4. **`construction`:** validation codes, the empty-result note, descriptions, `occam describe`, the JSON native format,
   report schema 2. Goal: an S6-style blind agent run at every milestone from here.
5. **`view`:** P9's limits and predicates, the browser pool (P10), P12's contract.
6. **`intersection`:** closed forms then the hybrid, `Unresolved`, `Undecided`, digest-tested edge box tests (P8).
7. **`booleans`:** pure phases, coincident surfaces as a gated family (O25), propagation to untouched faces (P1), the tally.
8. **`exchange`, `blends`, `release`:** unchanged, except that `blends` starts with the feasible-radius computation, the
   one part of the bracket test no spike touched.

## 8. What this design is least sure of

- **Fillets were never prototyped,** though L51 asks for that before structures freeze. If fillets need what records lack,
  such as a stored vertex star or edge convexity, the records grow.
- **Array-of-structs,** if a real profile finds a phase limited by traversing the store, such as the checker on 10^6 faces
  below 2 times at six cores.
- **No column store,** if NURBS-heavy work shows cross-instance lanes worth more than about 20% (S3-P3's AVX2 figure, O17).
  The batch from presentations would then be built, at a copy cost nobody has measured.
- **1e-6 mm.** If imported STEP models hold real features between 1e-7 and 1e-6 mm (O13), the default is too coarse.
- **Descriptions,** if blind runs on the real kernel do no better than S6's, or reports routinely pass a few kilobytes.
- **JSON as the native format,** if a 10^5-face model takes over a second to load.
- **Seams as edges.** S1 never compared them with a seam edge used twice; STEP faces crossing a seam, or agents puzzled by
  a hole of two faces, could change that.
- **How often `Undecided` happens.** P6 found the corpus never reaches the band edge, and no real model was counted.
