# rayon for the kernel's threads

**Decided by the user, 2026-11-10,** asked about `fearless_simd` and `rayon` under
[O5](../PLAN.md#7-decisions-the-user-still-owns) before `proving-ground.design`, with the recommendation from
[P11](../evidence/2026-11-09-p11.md) not to take `rayon` yet: "fearless_simd and rayon are fine to use." The kernel may
depend on `rayon`.

## What it means in practice

This section is Claude's working reading of the decision. The user can change it.

- The execution layer's first runner is `rayon`, not the small std-only pool P11 built. The two were level on the plain
  shapes and `rayon` was 10 to 17% ahead on nesting, short calls and grain left to the runner, so taking it also means
  occam does not own a scheduler.
- It sits behind P11's interface: an ordered `map` with explicit `Grain`, results in index order, no reductions, and
  `'static` closures. Only the crate that holds the execution layer names `rayon`, which keeps a swap to a small pool an
  adapter with no change at any call site. `Serial` stays the one-thread baseline and the runner inside each browser
  worker, which runs single-threaded ([P10](../evidence/2026-11-09-p10.md)).
- It enters a `Cargo.toml` with the first step that uses it, and its lines in `ci/dependencies.txt` cite this decision.
  Version 1.12.0 brings `rayon-core`, `crossbeam-deque`, `crossbeam-epoch`, `crossbeam-utils` and `either`, all MIT OR
  Apache-2.0, so [the no-copyleft decision](2026-11-08-no-copyleft.md) holds.
