# occam moves to Rust 1.100

**Decided by the user, 2026-11-16,** choosing "Move occam to 1.100". That day a worker ran occam-xtask's test binary
outside cargo, and rustup synced the laptop's `stable` channel from 1.99.1, which CI pinned, to 1.100.0. Under 1.100
the `compile_fail` test broke on cargo's new layout for build files, and the laptop's perf counts no longer matched the
record, which was measured on 1.99.1. Asked how the laptop should be set, the user chose to move occam to 1.100, over
pinning occam's work to 1.99.1 or setting the machine's default back.

## What it means in practice

This section is Claude's working reading of the decision. The user can change it.

- CI's one pin, in `.github/actions/setup/action.yml`, names 1.100.0. There is still no `rust-toolchain.toml`.
- The `compile_fail` test finds dependency files under cargo 1.100's layout, and any lint 1.100 adds is answered.
- The perf record is measured again on 1.100, once, after the PRs that were in flight on 1.99.1 have merged, and the
  determinism records are checked against it.
- Until this merges, occam's checks keep to 1.99.1 (`RUSTUP_TOOLCHAIN=1.99.1`), so the PRs in flight are measured as
  CI measures them.
- A test binary is never run outside cargo, which is how rustup came to update.
