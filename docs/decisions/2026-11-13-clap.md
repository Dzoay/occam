# The command line is parsed with clap

**Decided by the user, 2026-11-13,** asked during [`construction`](../plan/construction.md) before
`construction.commands`. That step gives `occam` five commands, `run`, `list`, `adjacent`, `describe` and `check`, each
with `--json` and many ids, and the command line until then parsed its one command, `distance`, by hand. The question
was whether it should take a parsing crate. There were three options:

- `clap`, with its derive macros (MIT OR Apache-2.0).
- `lexopt` (MIT), a tokeniser of one small crate with no dependencies. The subcommands and the help text would be
  written by hand.
- Staying hand-written, with no new crate.

The recommendation was the first, and the user said yes to it: "clap, derive (Recommended)".

## What it means in practice

This section is Claude's working reading of the decision. The user can change it.

- **Why clap.** The bracket test's agent has only the `occam` command and its reports
  ([the command line](../architecture/command-line.md)), so `occam --help` and each command's `--help` are what it
  reads first. clap writes them, and the usage a bad command line shows, from the same declarations that parse it. The
  subcommands are typed, and clap's errors map to `cli.bad-argument`, naming the argument, what was given and what was
  wanted.
- **The dependency.** `clap` is named in `occam-cli` only, with no default features and `std`, `derive`, `help`,
  `usage` and `error-context`: no colour or terminal detection, and no suggestions, which would bring in another crate.
  It brings in `clap_builder`, `clap_derive`, `clap_lex`, `anstyle` and `heck`, all MIT OR Apache-2.0. `clap_derive`
  uses `syn`, `quote` and `proc-macro2`, which were already in the tree. Each is in `ci/dependencies.txt` under this
  decision.
- **What clap does not decide.** The output stays occam's: a success or a refusal in one JSON form with `--json`, and
  the reports' wording without it. Only `--help` and a bad command line in words are clap's text.
